# دمج Frontend AgriShift مع Backend صاحبك

**دي نسخة Frontend مستقلة. ما عدّلناش أي ملف Python أو حساب علمي في الـBackend.**

## إيه اللي اتعمل؟

- صفحة رئيسية جديدة بألوان AgriShift، من غير استخدام شعار NASA في التصميم.
- لوحة تحكم متجاوبة مع الموبايل والكمبيوتر.
- نموذج بيانات أرض المزارع متوافق مع API النسخة المرفوعة (موسمين وموقع واحد فقط).
- إظهار 4 بدائل فعلية من `/api/analyze`، مع الاحتياج المائي التقديري، حالة الميزانية، الترتيب وشرح الفرضيات.
- فلترة حسب الميزانية، ترتيب حسب الطلب المائي، ومقارنة جانبية لما يصل إلى 3 خطط.
- رسم ET0 من `/api/monthly`، وحالة الاتصال بالـBackend، وتصدير تقرير JSON.
- عند تعديل أي مدخل، النتيجة القديمة بتتمسح عشان ما تتعرضش كأنها تخص المدخلات الجديدة.
- Saved Pilot Example من تقرير محفوظ في المشروع **ومتعلّم بوضوح إنه مش نتيجة حية**.

## تشغيلها مع Backend القديم للتجربة

1. فك ضغط `AgriShift-Working-MVP(1).zip` في فولدر منفصل للتجربة.
2. استبدل فولدر `frontend` بالفولدر اللي هنا فقط.
3. من جذر المشروع شغّل:

```powershell
python -m pip install -r requirements.txt
python start_agrishift.py
```

4. افتح `http://127.0.0.1:8000/`.

## تشغيلها من غير Backend

من داخل فولدر `frontend`:

```powershell
python -m http.server 8765
```

افتح `http://127.0.0.1:8765/dashboard.html?preview=1`.

النتائج اللي هتشوفها محفوظة من الـBackend الأصلي، **مش حسابات جديدة**. الزر الحقيقي Analyze مش هيشتغل إلا لما الـBackend متوصل.

## أهم تعليمات الدمج مع نسخة صاحبك الحديثة

**ما تنقلش ملفات Backend النسخة القديمة فوق شغل صاحبك.** انقل فولدر `frontend` الجديد فقط، وجرّب الـAPI عنده.

1. راجع ملف `API-CONTRACT.md` وشوف إذا نفس أسماء مدخلات ومخرجات `/api/analyze` لسه موجودة.
2. النسخة المرفوعة هنا بتقبل **موقع ثابت وموسمين فقط**. ما تضيفش Latitude/Longitude أو 4/6 مواسم للواجهة كأنهم شغالين إلا بعد التأكد من API صاحبك.
3. لو النسخة الجديدة بتعمل Dynamic Location، لازم `GET /api/climate` و`GET /api/monthly` يرجعوا داتا للموقع المحدد بدل الموقع القديم.
4. أي نتائج جديدة لازم تبان معها سنة البيانات، مصدرها، وافتراضاتها.
5. لو صاحبك غيّر JSON response، عدّل `decision-studio.js` على Contract موثق، مش بتخمين.
6. خلي نسخة واحدة هي الأصل (Git branches أو مجلد دمج)، وبلاش أي حد يكتب على ملفات التاني أثناء التطوير.

## اختبار الربط

```powershell
python verify_integration.py --base http://127.0.0.1:8000
```

راجع كمان يدويًا: تغيير الميزانية، تغيير الأولوية، فلترة الخطط، المقارنة الجانبية، عرض أسباب الخطة، وتصدير JSON. لازم كل القيم تكون من الـBackend.

## ملاحظات مهمة

- لا توجد ML predictions حقيقية في النسخة القديمة.
- تقديرات المياه لا تشمل effective rainfall أو root-zone water balance.
- الأرقام ليست توصيات زراعية حقلية معتمدة.
- Saved reference بيستخدم بيانات من `outputs/rotation_demo_2025_analogue/example_decision_report.json` في الملف الأصلي.
